# Strict B2B live email validation

Implementation prepared for Kickbox; activation requires KICKBOX_API_KEY in Supabase Vault, applying the dedicated service-only key RPC migration, and deploying auth-signup. No client key or additional mobile build is needed. Never deploy without a working key: new company-domain signups would correctly fail closed with a retry message.

Sequence: deterministic business email/alias rules → verified CAPTCHA or App Check → durable signup rate limit → partner policy validation → live email verification → consume onboarding authorization → create Auth user. The exact inbox.eu exception skips the paid provider but must still pass local syntax/alias checks, CAPTCHA and email confirmation. Every other locally eligible address is checked live. Domains already forbidden are rejected without incurring API charges.

Require a successful, schema-checked, matching-mailbox response with free=false, disposable=false, accept_all=false and result=deliverable. Role addresses (accounts@, compliance@) are allowed. Risky/undeliverable/catch-all results need a different verifiable mailbox. Unknown results, invalid responses, HTTP failures, missing keys and timeouts return retryable errors. No permissive fallback. No provider key, email, response body or request URL is logged. The configured vendor receives the full candidate email for verification. No cache; signup rate limits precede billable requests. Verification cost depends on the merchant's Kickbox plan/credits; no subscription or credits have been purchased.

Provider reference checked 2026-10-01: https://docs.kickbox.com/docs/single-verification-api — GET https://api.kickbox.com/v2/verify, email/apikey/timeout; timeout 6000ms with an 8000ms client deadline. Successful result alone does not prove business ownership or exclude undisclosed custom-domain aliases. Email confirmation and KYB remain required.
