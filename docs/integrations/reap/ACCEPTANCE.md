# Sandbox acceptance runbook

Use synthetic businesses, identities and documents only. Record timestamp, operation UUID, request digest, provider resource ID and result; never record credentials, PAN/CVV, access URLs or raw identity documents in test logs.

1. **Provisioning:** Obtain CaaS and Universal KYB compliance keys. Confirm REAP has enabled the selected UKYB product; no hosted or alternative verification-mode fallback. Confirm Standard Authorisation, commercial programme, currencies, supported countries, funding model and approved BorderPay design. Check authentication and scoped permissions using design/balance reads. Do not change the first API-key model without programme confirmation.
2. **Controlled environment:** Review the private sandbox SQL, apply only to the agreed isolated sandbox schema, configure evidence encryption and tenant membership. Keep programmes disabled until staff explicitly enables the synthetic programme. Connect Vault through server-side secret resolution. No new paid project is required.
3. **Webhook delivery:** Configure separate signed CaaS/compliance handlers after confirming current subscriptions. Confirm actual signatures against the documented sandbox keys. Verify durable acknowledgement within five seconds, duplicate automatic and manual replay, changed trace ID, altered payload, expired CaaS signature, concurrent delivery, unknown resource, database outage and retry recovery. Schedule and monitor background processing.
4. **Merchant onboarding:** Create BUSINESS/UKYB entity with stable external reference. Submit complete company/UBO pack. Save returned owner IDs matched by `externalUserId`, never by array order. Upload clean company documents and ordered owner evidence against the business URL. Fetch document manifest and verify every required file. Submit once. Exercise approved, rejected, additional-info and cancelled outcomes with sandbox simulator.
5. **Approval boundary:** Confirm approval plus `cardIssuanceEnabled=true`, valid merchant/cardholder membership and internal controls. Verify approved-without-grant fails. Pending/rejected businesses cannot receive cards. A company approval must not be substituted for an unrelated merchant approval.
6. **Card lifecycle:** Create one zero-allocation virtual business card with approved artwork. Repeat the exact operation safely; a changed body/key conflict must not create another card. Read back and bind card to merchant. Test freeze/unfreeze, spend controls and termination, verifying authoritative state after each change. Internal-review-failed cards must not be recreated to bypass a block.
7. **Funding:** Verify actual card currency and provider master allocation. Test a small simulated credit/debit, missing funds and a lost response. Reconcile UNKNOWN before any retry. Wire double-entry reservations/settlement only after validating provider financial semantics. Never affect production wallets.
8. **Transactions:** Simulate authorization, clearing, partial clearing, reversal, refund, decline, incremental/offline events where supported. Capture actual webhook/schema evidence. Do not relax the overlapping simulator schema until clarified. Confirm holds and settlements are distinct and replay cannot double-charge or double-credit.
9. **Disclosure:** Test short-lived hosted reveal (one-minute access URL), ownership check, recent authentication/SCA and no-store response. Restrict iframe origins to REAP-confirmed sandbox hosts. Confirm 3DS delivery and behaviour with sandbox-controlled cardholder contacts. Do not store sensitive card fields.
10. **Reconciliation:** Request daily/monthly files. Confirm approved download hosts, five-minute expiry, file format, stable row identifiers and pagination. Reconcile every currency from opening to closing balance, fees, refunds and master top-ups. Resolve every difference and missing record before considering ledger automation.
11. **Compliance operations:** Confirm where staff receive RFI details (public API references Zendesk), how replies/documents are accepted, fraud/dispute SLAs and emergency block workflows. Verify data access, retention, evidence deletion policy, key rotation and audit export. No general-purpose model decides approval.
12. **Release gate:** Attach provider test results, screenshots, cost/fee assumptions and unresolved issues to the draft PR. Review authenticated API/worker wiring and end-to-end merchant UI separately. Obtain production approval before connecting live credentials, issuing cards, funding or deploying.

All actual REAP execution steps remain pending sandbox access. Offline module tests do not mark them passed.
